## 3.0 配色体系（v3.0.0 起，改配色前必读）

- `--hue`（默认 184）是**唯一旋钮**；`--primary: hsl(var(--hue) …)`，旧名 `--cyan/--line/--glow-cyan/--grid-line/--head-glow`
  全为派生**别名**（勿改回硬编码 hex）；`--violet` 走 `var(--hue) + var(--vio-off)`。
- **语义色 `--magenta/--yellow/--green/--red` 不随 hue 旋转**（"能调气质，不能调语义"）。
- 三档只覆盖**参数**：dark `s100/l50`、light `s100/l24`、warm `s80/l25`；**light 的 24% 勿随手改**
  （与 WCAG 对比度挂钩，差 2 点就掉到 4.5 以下）。
- 墨色盘 `--ink-1..6` 由 hue 偏移派生；**浅底/暖底档必须另行覆盖**（暗墨色在浅底上是污渍）。
- `HUES`（theme-boot.js）与 `HUE_STOPS`（app.js）**必须逐值一致**；引导脚本 try 块内**不得有 early return**。
- 改配色**必须同时跑** `tests/cases/39-v3-0-0-b1-tokens.js` 与 `tests/cases/20-o9-色标.js`（后者真算对比度）。
- ⚠ **派生变量必须既"走 hsl(var(--hue)) 派生"又"确实被引用"**（R175d 已收紧）——
  `--grid-line`/`--head-glow` 曾因只查前者而零引用了整轮（改了毫无效果），批 B 才补上。

## 必须时刻记住的判据

**主题控点（二维罗盘，v3.0.0 起）**
- `#btn-theme` 只是 disclosure 触发器；面板 `.theme-menu`（`role=group`）内是**两个独立 radiogroup**
  （明度 3 项 + 色相 9 项）—— 12 项混装会让读屏把两组念成一个九选一。
- 选项必须是 `<button role="radio">`，不能换回 `<input type=radio>`（label 改 `e.target` 破坏 `closest()`；CSP 禁 `onchange`）。
- 方向键按 `closest('[role="radiogroup"]')` **组内隔离**；`renderNav()` 末尾必须 `syncThemeMenu(getTheme())`。
- 色相切换**不关面板**（试色是连续行为），明度切换关面板。改主题先看 `tests/cases/36-v2-9-4-uiverse.js`（46 条）。

**布局（3.0 各批次的硬约束）**
- **全站只有一个滚动容器（body）**；辅助栏一律 `sticky` + 四件套（`top: calc(var(--topbar-h) + 24px)` /
  `align-self: start` / `max-height: calc(100vh - …)` / `overflow-y: auto`）—— 少一条 sticky 会**静默失效**。
- **全站唯一允许 `position: fixed` 的元素**是 ≥1600px 的浮动目录（`.reading .toc`）。
- 侧栏类结构（TOC / 控制台导航 / 归档小工具）**1024 收起、768 单列**；移动端**不渲染**而非压窄。
- **TOC 的 DOM 在正文之后**（Tab 顺序靠布局而非 tabindex）；编号标（`.page-no`）是 h1 的**兄弟节点**。
- 布局问题一律用 `getBoundingClientRect()` 量矩形相交；**绝对定位角落元素 + `margin-left:auto` 弹性行 = 必然重叠**
  （给容器加内边距）；`fixed` 浮层压正文用 **body class** 让位。

**发布与验证**
- ⚠ **必须显式传 `"language": "static"`**；发布前 `npm run build` 必须全绿；**发布需用户当轮授权**（不得沿用上一轮）。
- **动过 `js/` 或 `css/` 就必须 bump 版本号** —— `?v=` 是唯一绕过缓存的机制，`--refresh-id` 对缓存零作用
  （代码改了但版本未发布时，用 `--refresh-id` 刷新 BUILD_ID 即可）。
- 线上验证**必须 GET**（禁用 `curl -I`）且带 `--compressed`；`verified:true` ≠ 已传播，**必须核 `?v=`/BUILD_ID**。

**代码与安全**
- **async 的 rejection 逃过同步 try** ⇒ `try{fn()}catch` 若 `fn` 可能是 async 必须补 `.catch()`。
- **模块可用性必须用「必需函数清单」判定**；跨文件全局一律**惰性取用 + 降级**，catch 分支绝不裸引用外部全局。
- CSP 无 `'unsafe-inline'` ⇒ **严禁内联 `<script>` 与 `onclick=`**；库字段带长度上限；错误对外脱敏。

**测试（本项目最贵的经验都在这）**
- **增删断言后必须 `npm run baseline`**；⚠ **新增 case 必须手动登记进 `tests/cases/manifest.json`**
  （工具只遍历已登记项，漏登记 = 永不进门禁；现已加差集检测当场报错）。
- ⚠ **反向验证会污染源码**：变异若触发**进程级未捕获错误**，`finally` 不执行 ⇒ 残留变异；
  而"逐字节恢复"自检会被**被污染的 orig 快照**骗过。防护：开场先写回 orig、结束用内容标记二次校验、
  变异必须"能跑"（别用 await/未定义函数）、**变异后要确认被测关系真的变了**。
- ⚠ **假绿三陷阱**：① 只查"关系存在"（挪动后仍成立）② 只查某 API 出现过（必须同时钉住赋值形式与它的使用）
  ③ 判据覆盖不全（如只查基类与某一级变体，漏掉中间级）。
- ⚠ **判据不许钉注释、不许钉"邻居"**：解释性注释（"为什么不用 `<a href="#x">`"）会被正则命中 ⇒ 假红，
  一律跑在 `stripComments` 之后；`A, B { }` 里要求 A 与 B 相邻 ⇒ 新增一个选择器就假红；CSS 声明断言用 `[^}]*` 跳过兄弟声明。
- **四个「全假绿」机制**：`SRC` 在 require 时读进内存 / `run()` 是 async / 反向验证的 require 缓存必须**连 case 文件自己一起清** /
  带大窗口的懒匹配会跨出函数边界（先按花括号配平抠出函数体 —— 配平**从 1 起**）。
- **先怀疑断言，再怀疑代码**；每条防回归断言都走一遍「摘掉修复 → 确认报红 → 恢复转绿」。

**浏览器自动化**
- 见 skill `agent-browser-windows`：它是**前台长驻进程**，且 `nohup … &` 的后台作业会随工具调用结束被回收 ⇒
  整条会话写成 `.sh` 用**工具侧 `run_in_background: true`** 跑；`eval` 脚本**必须放文件**用 `$(cat f)` 传入；
  交互验收必须用可信点击（`el.click()` 会造假故障）。
- ⚠ **本地起 http.server 拿不到云端数据**（首页/详情页会走错误分支）⇒ **布局与数据的验收必须在线上做**；
  本地只适合验收静态页（如 ABOUT）与主题/色相。
