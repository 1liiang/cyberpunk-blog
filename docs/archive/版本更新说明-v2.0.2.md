## 一、本次改进内容

### 1.1 内容分类标识：标签频段色标　`用户反馈 → 已完成`

**问题**：归档页每个条目只有「标题 + 日期」，没有标签、没有状态，**所有条目长得一模一样**，无法分辨类别。

数据其实一直在手边 —— `LIST_FIELDS` 早就取了 `tags` 字段，只是归档视图从未使用。线上实测文章 `id=4`（「不要回答！不要回答！不要回答！」）的 `tags` 就是 `[]`，**空标签是常态而非异常**，所以设计必须优雅处理它，而不是留白。

**方案**：把标签映射到站点既有的 5 个霓虹频段，用**四重编码**呈现。

| 频段 | 暗色 | 亮色（压暗档） | 图标 |
| ---- | ---- | ---- | ---- |
| `t0` | 青 `#00f0ff` | `#007a91` | ◆ |
| `t1` | 品红 `#ff2a6d` | `#c4104e` | ▲ |
| `t2` | 电光黄 `#f9f002` | `#7a6d00` | ■ |
| `t3` | 幽紫 `#b537f2` | `#7d1bb0` | ⬢ |
| `t4` | 荧光绿 `#05ffa1` | `#00784f` | ● |
| — | 中性灰 `var(--text-dim)` | 同 | ◇ 未分类 |

**为什么是「四重」而不是只用颜色**：色盲用户、灰度打印、高对比模式下色相会失效。图标（色相之外的第二通道）+ 底部 2px 下划线 + 边框，保证即使颜色全部丢失，仍能读出「这是哪一类」。图标与色号**同源推导**，不会出现「颜色说 A、图标说 B」的分裂。

**为什么颜色必须稳定**：色号由**标签名的 FNV-1a 哈希**推导，不是按出现顺序取。如果按顺序取色，「紫色 = 代码」这个肌肉记忆会在下一次列表变化时立刻失效。哈希保证同一标签在任何页面、任何时间、任何排序下都是同一个颜色。

> FNV-1a 用 `Math.imul` 做 32 位乘法，而不是 `a * 16777619` —— 后者超过 2⁵³ 后精度丢失，不同浏览器可能算出不同色号。

**空标签的决策**：显示中性灰「◇ 未分类」，且**刻意不占用 5 个频段中的任何一个**。灰色传达的信息就是「没有频段」，这与「属于某个频段」在语义上互斥，混进来会污染色板的含义。

### 1.2 跨页面配色统一

色标的用法不止归档页，三处同步接入，读者只需学一套颜色语言：

| 位置 | 呈现 |
| ---- | ---- |
| 归档条目 | 每行左侧 3px 频段色条 + 行首徽章 |
| 文章卡片 | `card-meta` 里的标签带频段色（原先固定紫色） |
| 标签总览 | 按**热度排名**分配色号，前 5 名互不重复 |

**关于标签总览为何用另一套规则**：它的职责是「一次看到全部频段」，所以按使用次数排名分配 —— 用得最多的拿 `t0`，次多的拿 `t1`，「色号 = 频段热度」成为一条可读的规律。第 6 名起退回按名字哈希（不再声称"热度第 N"，只保证"这个标签恒定这个色"）。

> 顺带修掉一处旧写法：`i % TAG_TONES` 会让第 8 名与第 3 名撞色（热度相差一倍却是同一颜色，反而误导）。断言的写法教训见 2.2 节。

### 1.3 可读性修正：亮色主题对比度临界值

写测试时用 WCAG 公式**实算**了对比度，抓到一个真问题：

**亮色档 `--cyan` (`#007a91`) 对页面底色 `#eef2f8` 的对比度只有 4.46:1，低于 WCAG AA 的 4.5:1。**

色标文字是 10.5px 小字，差这 0.04 就是「合格」与「勉强看得见」的分界。

**修法**：给文字色掺入主体文字色，而不是硬调色板：

```css
--tone-ink: color-mix(in srgb, var(--tone) 82%, var(--text-bright));
```

`--text-bright` 在暗色主题下是近白、亮色下是近黑 —— **掺入它在两个方向都是增加对比**，于是同一条公式同时修好两套主题，色相仍由 `--tone` 贡献 82%，肉眼还是那个频段的颜色。

修正后实测：

| 频段 | 修正前 | 修正后 |
| ---- | ---- | ---- |
| 青 | 4.46 ✗ | **5.70** ✓ |
| 品红 | 5.30 | 6.90 |
| 电光黄 | 4.70 | 6.00 |
| 幽紫 | 7.00 | 8.50 |
| 荧光绿 | 4.90 | 6.20 |

### 1.4 `bump.js` 新增改号模式　`工具链 → 已完成`

**背景**：本轮要把一个「已 bump 但从未发布」的版本号改掉（`2.1.0` → `2.0.2`），原校验「新号必须 > 本地 BUILD」会拦住这个合法操作。

但那条校验守的**不变量是对的，不能简单删掉** —— 它防的是「用一个已发布过的号，导致 `?v=` 缓存键不变、用户拿到旧文件却以为更新了」。

**做法**：新增 `--renumber` 模式，把比对基准从「本地 BUILD」换成「**已发布版本**」，并要求调用者显式声明线上版本：

```bash
node tools/bump.js 2.0.2 --renumber --published=2.0.1 \
  --title="..." --item="..."
```

因为脚本无法自行探测线上版本，所以 `--published` 是**必填**；且校验「新号必须高于已发布版本」，复用旧号依然被拒。

**四条拒绝路径**（全部有断言覆盖 + 反向验证）：

| 场景 | 行为 |
| ---- | ---- |
| 常规模式尝试递减 | 拒绝，并提示可用 `--renumber` |
| `--renumber` 缺 `--published` | 拒绝（安全性取决于新号未用过，必须声明基准） |
| `--published` 格式非 `x.y.z` | 拒绝 |
| 新号 ≤ 已发布版本 | 拒绝（防复用已用过的缓存键） |

### 1.5 控制台列表改事件委托

原实现给每个条目单独挂 `addEventListener`，渲染 N 条就挂 N 个监听。改为在常驻的 `#app` 节点上挂**唯一一个委托监听**，重渲染不叠加、也不随条目数增长。

条目内嵌的「编辑」按钮仍能命中（`closest('[data-edit]')` 会向上找到条目本体）。

### 1.6 `package.json` 版本同步

`package.json` 的 `version` 长期停留在 `2.0.0`（落后两个版本）。虽然它不参与页面渲染，但 v2.0.0 的日志里把 `package.json` 称作「**版本单一数据源**」之一 —— 说法与事实不符就是文档失真。

已同步为 `2.0.2`，并加 R61h 断言守住一致性。

### 2.2 反向验证：本轮抓出 5 处「假绿」

按项目铁律，每条新断言都要**注入 bug 确认它会转红**。这个过程抓出的不是代码 bug，而是**测试自身的漏洞** —— 它们全绿，但什么也没测住：

| # | 呈现形式 | 为什么是假绿 | 修正 |
| - | ---- | ---- | ---- |
| ① | 色号范围用 12 个固定样本抽查 | 「色号 +1」越界后，样本恰好没有一个落到 4，越界检查照样通过 | 改为**穷举 720 个输入** + 断言「5 个色号全部可达」（防 `%3` 造成死频段） |
| ② | 对比度公式的混合比例**写死在测试里** | 有人把 CSS 的 82% 改成 100%（= 直接用 `--tone`，青色掉回 4.46），断言仍算出漂亮的数字 | 改为**从 CSS 现读现算** |
| ③ | 断言「每个 `tN` 都解析到某个合法变量」 | 把 `t4` 也写成 `var(--cyan)` 完全通过，但 5 个频段实际只剩 4 个可区分 | 补断言「5 个 `tN` 必须映射到 5 个**互不相同**的变量」 |
| ④ | 断言 `/--renumber/.test(src)` | 用法说明、注释、错误提示里都含这个词，删掉选项解析那一行照样绿 | 改钉**可执行结构**（参数解析语句 + 守卫条件） |
| ⑤ | 检查 `hasOwnProperty(k)` | 只拦住 undefined 值；属性存在但值为 `undefined` 时漏网 | 改直接检查值（本次未触发，同批排查中发现） |

**共同教训**：断言要钉**真·单一数据源**或**行为**，不要钉「源码里出现过某个词」或「测试里复制的一份常量」。前者会被注释和文档救活，后者会与实现悄悄走散。

## 四、已知取舍（不是遗漏，是决定）

1. **亮色档的黄不再是"黄"** —— 压成了 `#7a6d00`（橄榄色）。这是黄色系在浅底上达到 AA 对比度必须付的代价，属物理限制而非实现缺陷。若未来放宽到 4:1 或改用第六个色相可缓解。

2. **样本文本量导致部分频段在真实数据下未出现** —— 线上目前只有 2 篇已发布文章，`t2`/`t4` 等频段在真实页面暂时看不到。色号映射已用穷举断言验证全部可达，但**真实数据的视觉确认要等文章变多**。

3. **标签总览与归档页用两套色号规则** —— 前者按热度排名、后者按名字哈希。刻意为之（职责不同），但代价是「同一个标签在两个页面的颜色可能不同」。若希望全站一套规则，改 `rankedTones` 直接返回 `tagTone` 即可。

4. **色标只在列表类视图生效** —— 文章详情页的 `post-meta` 沿用原有 `tag-chip`（已带频段色），但 `md-body` 正文里的标签文本不做着色。正文属于作者内容，不应被站点视觉规则侵入。
