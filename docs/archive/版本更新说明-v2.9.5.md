## 二、逐项说明

### ① 双色内发光卡片

**原组件的做法**：hover 时叠 8 层 box-shadow——5 层 `inset`（白 + 品红 + 青，左右各两道往里渗）加 3 层外发光，配 `#0ff` / `#f0f` 这类高饱和原色。

**借来的部分**：`inset` 阴影**左右对冲**这个手法。青光从左缘往里渗（`inset 26px 0 …`）、品红从右缘往里渗（`inset -26px 0 …`），中间再垫一层无偏移的大半径 inset 给整个卡面打底。这是纯 `box-shadow` 实现，**零新增 DOM**——这点很关键，因为 `.post-card::before` / `::after` 都已经被角标装饰占用了。

**换掉的部分**：所有颜色从硬编码换成 `color-mix(in srgb, var(--cyan) …)`。原组件的 `#0ff` 在暗底上是霓虹、在亮色档的 `#eef2f8` 浅底上就是刺眼原色。走变量后，亮色档自动落到压暗后的 `#007a91`，暖色档落到 `#0d6b74`——三个主题下都是"同一支霓虹"而不是三个色块。

**保留的部分**：原有的顶部霓虹（`0 0 24px`）和落地投影（`0 14px 40px`）没动。它们负责"卡片浮起来"，inset 负责"内部点亮"，两层职责不同。

---

### ② 旋转光晕搜索框

**原组件的做法**：`#poda` 里塞了 `.glow` / `.darkBorderBg` ×3 / `.white` / `.border` / `.filterBorder` 共 7 层 div，每层 `overflow:hidden` + `border-radius` + 模糊，各挂一个 600~999px 的 `conic-gradient` 伪元素，靠 `:hover` / `:focus-within` 改 `rotate()` 角度。

**借来的部分**：只有「**大尺寸 conic-gradient，只在两处留亮弧，聚焦时让角度转起来**」这一件事。落地收紧成**一个宿主 + 一个伪元素**：

- 输入框外包一层 `<div class="search-field">`。必须有它——`<input>` 不支持伪元素，光晕没地方挂；
- 用 `@property` 把 `--halo-spin` 注册成 `<angle>`。**这一行是整个技法能否成立的关键**：自定义属性不注册的话，keyframes 动它只会离散跳变（在 50% 处瞬切），根本看不出"旋转"，只看得出"闪了一下"；
- 不用 `overflow:hidden` 裁切，改用 `blur(10px)` + `inset:-9px` 外扩，光晕自然从输入框边缘往外渗，省掉一层嵌套。

**三个设计取舍**：

1. **两段亮弧用青 + 品红**，与站点的双色语言对位（原组件是紫 + 品红）；
2. **7 秒一圈**。原组件是 4s，但那是营销页的首因效应；搜索框是要盯着输入的，转快了就是频闪干扰；
3. **静止态 `opacity: 0`**。光晕只在聚焦时出现——它同时是"此处已聚焦"的视觉信号，常亮就失去这个意义了。

**结构代价**：`.search-input` 的 `flex:1; min-width:220px` 移交给了宿主，输入框改 `width:100%`。按钮留在 `.search-bar` 直下，没有被裹进宿主——`.btn` 的背景几乎全透明，裹进去光晕会从按钮后面漏出来。

---

### ③ 扫描线霓虹输入框

**原组件的做法**：`clip-path` 九边形装甲缺口 + 双向 `repeating-linear-gradient` 扫描线 + 两段动画（`backglitch` 50ms 无限抖动 inset 阴影、`blinkShadowsFilter` 8s 无限跳变的双向 `drop-shadow`）。

**借来的部分**：装甲切角 + 扫描线这两个**形态语言**。切角换成本站自己的 `--clip-corner-sm`（9px，与全站 `--clip-corner` 的 14px 同一套几何语言——输入框只有 ~40px 高，14px 会吃掉近三分之一宽度）；扫描线是 `repeating-linear-gradient` 直接铺在输入框背景上，青色只给 **6% 透明度**，是"纹理"不是"花纹"。聚焦时叠一道自左向右的青色扫光（原组件的 focus 渐变）。

**刻意不搬的两段动画**（这条有反向断言守着，见 R177e/R177f）：

- `backglitch`：50ms 无限抖动的高频闪烁，是**光敏性癫痫风险**，且与本站"装饰动画在减少动效下必须停"的承诺直接冲突；
- `blinkShadowsFilter`：大范围双向重影跳变，放在编辑这种要久看的界面上就是持续噪音。

**范围控制**：只圈编辑器的四个文本输入（`#ed-title` / `#ed-summary` / `#ed-tags` / `#ed-cover`），**没有**顺着 `.field` 全局铺开——登录框、标签管理、封面引用框保持原样。R177g 这条断言守着这个边界：谁往 `.field` 全局加 `clip-path`，门禁当场报红。

## 三、无障碍与既有约束的遵守

| 约束 | 本版如何满足 |
| ---- | ---- |
| E1 铁律：hover 效果必须在 `@media (hover: hover)` 内 | 卡片对冲光写在既有的 hover 媒体块里；光晕走 `:focus-within`，不依赖 hover |
| R66m：`transition` 禁止裸写时长 | 新增 transition 只有 `opacity var(--t-slow) ease`；光晕转速走 `animation`（R66m 只管 transition，与 `.toast` 的既有写法一致） |
| R72k：时长型 `--t-*` 必须在 reduce 块归零 | **本版没有新增任何 `--t-*` 时长变量**——转速用裸 `7s` 写在 `animation` 里，因此在 reduce 块里**显式**关掉，不指望兜底 |
| R112e：reduce 块内裸选择器行数 < 20（预算 0） | 新增的 reduce 规则写成**单行**（含 `}` 的行不计入） |
| 减少动效下不丢信息 | 光晕只停转、不隐藏（它同时是聚焦指示物）——与 v2.9.4 罗盘环同一原则 |
| 触屏（`hover: none`） | 未新增触屏相关规则；卡片 hover 原本就在 hover 媒体块内，触屏天然不触发 |
