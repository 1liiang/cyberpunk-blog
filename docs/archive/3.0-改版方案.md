- bento 网格是年度主流（注意它的"运营悖论"：模块塞多了会变重）；

## 3. 配色体系重构：一个变量 = 任意颜色（回应「可以多种颜色」）

### 3.1 现状为什么"锁死"了

现在有 3 套主题（dark/light/warm），每套手写约 20 个颜色变量；再加上 5 个固定霓虹（青/品红/紫/黄/绿）。**想加一套配色 = 再手写 20 个变量**，所以只能停在 3 套。这就是"不局限于如今这样"要打破的东西。

### 3.2 新体系：三层色彩 + 单个色相旋钮

```css
:root {
  --hue: 187;                        /* ★ 唯一旋钮：0~360，青 187 为默认 */
  --hue-sat: 92%;                    /* 饱和上限，亮色档自动下调 */

  /* ① chrome 层：界面骨架色（由 hue 派生，随旋钮整体变色） */
  --primary:      hsl(var(--hue) var(--hue-sat) 58%);
  --primary-dim:  hsl(var(--hue) 60% 42%);
  --primary-line: hsl(var(--hue) 70% 55% / 0.35);
  --primary-glow: 0 0 12px hsl(var(--hue) 92% 60% / 0.55);
  --bg-1: hsl(var(--hue) 22% 7%);    /* 暗底也带一丝主色，整体更"成套" */

  /* ② content 层：墨色盘（低饱和，供 bento 模块分区用）—— 色相固定偏移，不随旋钮旋转 */
  --ink-1: hsl(calc(var(--hue) + 0)   28% 14%);
  --ink-2: hsl(calc(var(--hue) + 40)  28% 14%);
  --ink-3: hsl(calc(var(--hue) + 80)  24% 15%);
  --ink-4: hsl(calc(var(--hue) + 140) 22% 15%);
  --ink-5: hsl(calc(var(--hue) + 200) 20% 15%);

  /* ③ semantic 层：语义色 —— 固定不旋转（"色即信号"不能被用户调色破坏） */
  --sig-flow:  hsl(330 92% 60%);   /* 品红：流逝 / 警示 */
  --sig-live:  hsl(150 92% 58%);   /* 绿：在线 / 成功 */
  --sig-warn:  hsl(48 96% 60%);    /* 黄：高亮 / 提醒 */
}
```

三层各自的纪律：
1. **chrome 层**随 `--hue` 整体变色 —— 换一个数字，全站气质就换（青→蓝→紫→品红→桃→绿→琥珀）。
2. **content 层**是"围绕主色相的邻近色环"，给 bento 模块做低饱和分区（taozhiyy 的多墨色思路，用 hue 偏移实现，**不需要手写 8 组颜色**）。
3. **semantic 层**固定：`--sig-flow` 永远是品红、`--sig-live` 永远是绿。**用户能调气质，不能调语义**——这是把"多彩"和"可读"绑在一起的关键闸门。

### 3.3 色相预设盘（9 档）+ 自由微调

| 档位 | hue | 气质 |
| --- | --- | --- |
| 青（默认） | 187 | 现在这个样子，冷感终端 |
| 电蓝 | 217 | 更"硬件"，接近 Cyberpunk 2077 的系统色 |
| 靛 | 250 | 冷静、夜间阅读 |
| 紫 | 285 | neon noir |
| 品红 | 330 | 强烈、夜城招牌 |
| 桃 | 350 | 呼应 taozhiyy 的温柔感 |
| 橙 | 25 | 暖、警示感 |
| 琥珀 | 38 | 暖纸（替代现有 warm 档） |
| 苔绿 | 145 | 有机、低刺激 |

**主题罗盘的升级**：现有三档罗盘（v2.9.4 建的 `role=radiogroup` + `<button role=radio>` + roving tabindex）**结构不动**，从一维扩成二维：
- 第一排：明度三档（暗 / 亮 / 暖纸）—— 现有三档，保留
- 第二排：色相九档 —— 新增，同样 `role="radio"` + 方向键换档
- 无障碍契约完全沿用（方向键 / Escape / 外部点击 / roving tabindex），**现有 33 条断言可原地复用**，只是把"3 个 radio"扩到"12 个 radio"

存储沿用现有机制：`localStorage` 存 `hue` 与 `mode`，**由 `theme-boot.js` 在首绘前同步应用**（本站已有这个防闪烁脚本，与 Fuwari 用阻断脚本设 `--hue` 是同一条路子，不需要新增机制）。

### 3.4 墨色在 bento 里的分配（避免变花）

规则三条：
1. **一个模块一种墨色**（`MODULE 01 → --ink-1` … `MODULE 06 → --ink-1` 循环，或按语义分配）；
2. **墨色只用在底与边**，模块内的正文、数字、图标仍走 `--text` 与 `--primary`；
3. **每屏最多一个模块用 `--primary` 实色强调**（守住"霓虹 ≤ 15% 表面积"的红线——墨色是 12~15% 低浓度，不计入霓虹表面积）。

### 3.5 可访问性护栏（必须一起做，否则"多彩"会变成"难读"）

| 风险 | 护栏 |
| --- | --- |
| 亮色档下高饱和刺眼 | 亮色档把 `--hue-sat` 自动降到 60~70%，并沿用现有 `--glow-*` 亮色收敛逻辑 |
| 任意 hue 下正文对比度不足 | 正文/背景不用 hue 派生，**始终走 `--text` 的中性色**；hue 只作用于强调件 |
| 色盲用户无法区分语义 | 语义色固定 + 已有"色相之外叠加图标/下划线"的做法（v2.0.2 标签色标）继续生效 |
| 用户调出"丑配色" | 色相盘只给 9 个预设档（不开放自由滑杆），保证每一档都验证过 |

## 5. 维度二 · 骨架（谁固定、谁滚动）

**总原则不变：全站只有一个滚动容器（`body`）**；不做主内容区内部滚动；不做 `fixed` 侧栏。

| 区域 | 桌面 | 平板 | 移动 | 要点 |
| --- | --- | --- | --- | --- |
| **页头 topbar** | `sticky top:0`，高 `--topbar-h`（64px） | 同左 | 缩到 56px | 高度变量化 |
| **Banner 层（新，借 Fuwari）** | 页头之下的固定高度带（首页更高），**文档流** | 降高 | 降高 | `--banner-h` / `--banner-h-home`；高度按视口算并**取 4 的倍数**保文字清晰 |
| **首屏 Hero（新，借 taozhiyy+Fuwari）** | 由 Banner + 标题 + 编号 + 滚动引导构成，`min-height: min(100vh - var(--topbar-h), 720px)` | 72vh | 60vh | 文档流；全站唯一允许"滚动叙事"的位置 |
| **辅助栏 · TOC（详情页）** | 右侧 240px `sticky`，`top: calc(var(--topbar-h) + 24px)` | 折叠块 | 不渲染 | `align-self: flex-start` + `max-height: calc(100vh - var(--topbar-h) - 48px)` + `overflow: auto` |
| **浮动 TOC（新，借 Fuwari）** | `min-width: 1600px` 才出现（外层 absolute + 内层 `fixed top: calc(var(--topbar-h) + 16px)`） | 隐藏 | 隐藏 | 超宽屏的第二种读法；**不用 fixed 主侧栏**，只有这个纯目录面板允许 fixed |
| **管理台导航** | 左侧 220px `sticky` | 顶部标签条 | 顶部标签条 | 与 TOC 同配方 |
| **主内容区** | 文档流，宽度按页型 | 同左 | 单栏 | 唯一滚动源 |
| **页脚** | 文档流 | 同左 | 同左 | 错峰入场最后一拍（150ms） |
| **既有浮层**（电台 dock / 返回顶部 / 主题面板） | 保持 `fixed` | 同左 | 缩为图标 | 已有 body-class 让位机制，不动 |

## 6. 维度三 · 栅格与分栏

### 6.1 容器三档

```css
:root { --w-read: 760px; --w-page: 1000px; --w-wide: 1240px; }
```

### 6.2 三种栅格

```css
/* A. 首页 bento：12 列 */
.bento { display: grid; grid-template-columns: repeat(12, 1fr); gap: var(--s5); }
.bento > * { grid-column: span 6; }
.bento > .span-4 { grid-column: span 4; }
.bento > .span-8 { grid-column: span 8; }
.bento > .span-12 { grid-column: span 12; }

/* B. 详情页：正文 + 240 目录（与 Fuwari 的 17.5rem=280px 同区间，取窄值保阅读） */
.reading { display: grid; grid-template-columns: minmax(0, 1fr) 240px; gap: 44px; max-width: var(--w-page); }

/* C. 管理台：导航 + 弹性内容 */
.console { display: grid; grid-template-columns: 220px minmax(0, 1fr); gap: var(--s7); max-width: var(--w-wide); }
```

> `minmax(0, 1fr)` 不可省：没有它长代码块/长表格会撑破栅格列。

### 6.3 断点收敛：5 个散值 → 4 个体系值

| 新断点 | 语义 | 取代 |
| --- | --- | --- |
| **1280px** | 宽屏 → 标准 | `1400` |
| **1024px** | 辅助栏收起（TOC 折叠、管理台导航转横向） | `1000`、`860` |
| **768px** | 全部单栏 | `720` |
| **480px** | 紧凑间距档 | `640` |

另加两个**只在超宽屏生效**的增强断点：`1600px`（出浮动 TOC）、`1920px`（bento 允许 4 模块一行）。
写法取向：**新骨架层用移动优先**（`@media (min-width: …)`），同一页面不与旧 `max-width` 混用（详见第 2 版论述，结论不变）。

## 7. 维度四 · 间距与节奏

### 7.1 4px 基准九级刻度

```css
:root { --s1: 4px; --s2: 8px; --s3: 12px; --s4: 16px; --s5: 20px; --s6: 24px; --s7: 32px; --s8: 48px; --s9: 64px; }
```

现状值映射：`2/3/4/5px → --s1`｜`6/7/8/9/10px → --s2`｜`12/14px → --s3`｜`18px → --s4`｜`20/26px → --s5/--s6`｜`34px → --s7`。

### 7.2 三档节奏

| 节奏 | 用于 | 区块 | 卡片间距 | 卡片内距 |
| --- | --- | --- | --- | --- |
| 紧凑 | 首页 bento、管理台 | `--s7` | `--s5` | `--s5` |
| 标准 | 列表页 | `--s8` | `--s4` | `--s5` |

### 7.3 同页两档（借 taozhiyy 的「Hero → 片段」）

首屏 Hero 用**沉浸节奏**（`--s9` 上下），下面 bento 立刻切**紧凑**（`--s5/--s7`）。密度随"目标"变，不随品味变。

### 7.4 错峰入场（借 Fuwari 的 `onload-animation`）

每次路由切换后，各区块依次入场，delay 阶梯：**页头 0ms → 侧栏 50ms → 主内容 90ms → 页脚 150ms**。
- 只在**进入页面**时跑一次（不是滚动触发），用现有 `route()` 生命周期挂一个 body class，动画交给 CSS；
- 全部裸时长 animation ⇒ **必须在 reduce 块显式关闭**（单行写法，守 R112e 预算），并与现有 `--t-*` 体系对齐；
- 移动端缩短为 2 拍（页头 + 主内容），避免小屏拖沓。

## 11. 影响面、风险与「不做清单」

| 风险 | 应对 |
| --- | --- |
| 861 条断言绑定旧选择器 | **新骨架一律新增类名**（`.bento` / `.reading` / `.console` / `.hero`），旧类名（`.wrap` / `.page-head` / `.post-card`）保留为别名；改 px 的断言逐批改写并 `baseline` |

| 键盘可达 | 侧栏/TOC 节点置 DOM 之后；`aria-current` 标记当前位置；浮动 TOC 不作为唯一导航途径 |
